**Verdict: NOT READY**

Not verified live: README:13 and README:20 (plugin session behaviour), and the triager payloads, which were reasoned from the prompt. Interruption rates are estimates, not measurements. Every item marked tested was run on Semgrep 1.184.0, gitleaks, PMD, Ruff 0.17.4 and git 2.38 on this machine.

**The three fixes that matter most before showing this to other engineers**

1. **Make the secret claim true.** Redact secret lines from `snippet` and packet context (`normalize.py:97`, `packet.py:64`), force secret clusters to `needs_human` in code, and strip values from Bandit messages. The headline security claim at DESIGN:389 is currently false, and it is the first thing a security-minded reader will test.
2. **Close the review-evasion paths in one change.** Prefix targets with `./`, add `--text`, replace the diff parser with one that tracks hunks and splits only on `\n`, filter symlinks, and fail loudly when tools did not run. Today one empty file or one `.gitattributes` line gives "No findings" with exit 0.
3. **Stop trusting repo config and untrusted text in the command layer.** Remove `test_command` from `.sift.toml`, resolve and validate config in Python rather than in the prompt, move `in:` and `message:` inside the envelope, and make the citation check verify a real file and line and reject duplicate verdicts.
